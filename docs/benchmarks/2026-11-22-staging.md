# Staging deployment and verification (2026-11-22)

The Terraform in `infra/terraform` was applied to an AWS workload account (us-east-1),
verified, and destroyed the same day. Design: [ADR-0011](../adr/0011-private-staging-on-aws.md).

- Model providers: `fake` for chat and embeddings. The account's Bedrock quotas for
  Claude Haiku 5.5 and Titan Text Embeddings V2 are still 0 (ADR-0004), so this run
  verifies the infrastructure and the security controls, not model quality.
- Scope: 90 resources in two phases (network, data stores, identity and registry first;
  ECS services after the images were pushed), then migrations, seeding, 7 demo users and
  12 policy PDFs ingested through the API (S3 → SQS → worker).

## Policy validation

IAM Access Analyzer `validate-policy` on the deployed policies (5 inline role policies,
5 trust policies, the bucket policy and the KMS key policy; 12 in total): 2 findings on the first run
(a redundant Bedrock model ARN; an ARN operator on a string condition key), both fixed and
applied; 0 findings after.

## Issues found and fixed during the deployment

| Issue | Fix |
| --- | --- |
| Cognito has no interface endpoint in one of the two AZs | each endpoint goes in a subnet whose AZ the service supports |
| `rds.force_ssl` and ECS container definitions showed a difference on every plan | declared as AWS stores them; plans are empty after an apply |
| API Gateway request IDs (`HREdzhlCIAMEVHQ=`) were rejected by the API's request ID pattern, breaking log correlation | `=` accepted; gateway and API logs now share the ID |
| Docker on Windows could not store the ECR login token | images are pushed from a Linux Docker CLI container |
